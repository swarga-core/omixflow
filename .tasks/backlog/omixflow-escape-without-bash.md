**Контекст.** `protocol/worktree.md`, «Ловушки», «Escape в параметрах инструментов»: `\uXXXX` в
параметрах инструментов правки и в тексте команд раскодируется в сам символ; escape пишется
скриптом, собирающим обратный слеш через `chr(92)`, результат проверяется байтами (`grep -nP`,
`cat -v`); «касается агентов, оркестратора и лида». То же — в `agents/coder.md`, «Bytes, not intent».
У architect'а `tools: Read, Write, Edit, Glob, Grep, mcp__serena__*` — Bash нет, рецепт ему недоступен.

**Проблема.**
- mewria MEW-32 (проверка `#if MEWRIA_DEV`): Edit architect'а раскодировал `\u`-escape в spec.md
  (S12, затем D2, D4) — примеры обхода проверки превратились в само нарушение, вопреки сценарию S1.
- Поймал coder пробой; coder на проходе фиксов восстановил S12 скриптом, architect затем
  восстановил D2/D4 плейсхолдером и заменой Edit'ом и сверил по байтам (log.md MEW-32, стр. 123–124).
  Путь нашли сами, протокол его не называет.

**Предложение.**
1. `worktree.md`, «Escape в параметрах инструментов»: путь для агентов без Bash — в тексте
   плейсхолдер (`@@U0023@@`), затем замена Edit'ом, где `new_string` несёт удвоенный обратный слеш
   (`\\u0023` в параметре — `#` в файле); сверка — Grep по литералу (`\\u0023`, режим без regex
   или экранированный) и по отсутствию самого символа; провал — сказать оркестратору, тот правит
   скриптом.
2. `agents/architect.md` (и researcher, у кого тоже нет Bash): ссылка на этот путь там, где
   architect пишет спеку с escape-последовательностями; в отчёте — строка «escape сверены Grep'ом».
3. Bash architect'у не давать: ему он нужен только здесь, а Bash расширяет поверхность (изоляция,
   разрешения).

**Критерии приёмки.** `worktree.md` называет путь для агентов без Bash; `architect.md` ссылается на
него; проба — architect пишет в spec строку с литералом `#if` без раскодирования, сверка Grep'ом
зелёная.

**Реализация 0.9.7 (поправка к предложению).** Проба 2026-10-20 (Claude Code 2.1.304, Edit и Write
основной сессии): одиночный `\u0023` в параметре ложится символом `#`, удвоенный `\\u0023` —
двумя слешами, а не одним: п. 1 предложения неверен. Раскодирование однопроходное, поэтому
рабочий путь — обратный слеш самого escape'а как `\u005C`: `\u005Cu0023` даёт в файле `\u0023`.
Сверка — Read строки (вывод показывает escape); Grep'ом не проверяли. Researcher'а правка не касается:
Bash у него есть. Записано в `worktree.md` («Escape в параметрах инструментов») и в
`architect.md` («Escapes without Bash», строка отчёта «escapes checked by Read»).
