**Контекст.** MEW-8: оркестратор сессии после составных команд с `cd` оказался с рабочим
каталогом `.tasks/board`, затем `sim/package/Runtime/Pools`; лид — тоже в `.tasks/board`.
Харнесс Claude Code сохраняет каталог между вызовами Bash: `cd` в одной команде меняет его
для всех следующих.

**Проблема.**
- При трекере kanban `.tasks/board` — worktree ветки `board` внутри основного дерева. Сессия,
  чей каталог остался там, следующим `git add` / `git commit` (коммит шага, артефактов)
  коммитит в ветку доски, а не в ветку задачи; хуки проекта в worktree доски не работают
  (относительный `core.hooksPath`), так что ничего не остановит. `board.py` такой коммит
  не увидит до следующей транзакции (rebase / push унесёт его на `origin`).
- `protocol/worktree.md`, «Ловушки», пишет обратное: «cwd сбрасывается… может вернуться
  в основное дерево». На деле каталог сохраняется после `cd`; правило «всегда `git -C`»
  верное, но обосновано не тем случаем и не говорит про `cd`.
- `adapters/tracker/kanban.md` не запрещает заходить в worktree доски.

**Предложение.**
- `protocol/worktree.md`, «Ловушки»: каталог сессии сохраняется между вызовами Bash; `cd`
  в составной команде запрещён — абсолютные пути и `git -C {path}`; если каталог ушёл —
  вернуть его в корень проекта до любой git-команды.
- `adapters/tracker/kanban.md`: в `.tasks/board` не заходить; доску читать `board.py` (`get`,
  `list`, `path`) или `git -C .tasks/board` только для чтения; правки — только скриптом.
- Скилы implement, review, finalize перед коммитом сверяют `git rev-parse --show-toplevel`
  и ветку с ожидаемыми (корень проекта и ветка задачи).

**Критерии приёмки.** Ловушка переписана; адаптер kanban запрещает `cd` в доску; проверка
корня и ветки перед коммитом в скилах.
