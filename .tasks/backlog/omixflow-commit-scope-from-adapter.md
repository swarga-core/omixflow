**Контекст.** Скилы задают сообщения коммитов шаблонами: implement 2.5 — `{feat|fix|refactor|
test|docs}: {описание шага}`, review (коммит фиксов прохода) — буквально
`fix: address review findings for {id} (pass {N})`. Порт workspace (`adapters/workspace/
PORT.md`) правила об области коммита не задаёт. Проектный адаптер mewria
(`.claude/omixflow/workspace/git.md`, «Сообщение»): «тип по формату скила с областью
зоны — `feat(sim): …`, `fix(client): …` …; задача в нескольких зонах — область главной».

**Проблема.** MEW-25: коммит фиксов прохода ревью `503e4da` ушёл без области — оркестратор
взял шаблон скила review дословно, ревьюер кода отметил нарушение адаптера. В шаблоне шага
тип выбирает оркестратор, и область он подставлял; в шаблоне фиксов подставить некуда.

**Предложение.**
- Порт workspace: необязательный раздел адаптера «Сообщение коммита» — область (scope) и её
  выбор; без раздела — шаблоны скилов как есть.
- Шаблоны скилов (implement 2.5, review — фиксы прохода и починка гейта, finalize — squash,
  sync — слияние) пишутся `{type}[({область})]: …` со ссылкой на этот раздел адаптера.
- Линт: шаблоны коммитов в скилах содержат место под область.

**Критерии приёмки.** В mewria коммит фиксов ревью получает область зоны без правки
скила; без раздела в адаптере сообщения прежние.
