**Контекст.** MEW-6, мутационные прогоны coder'а на C# (`dotnet build` / `dotnet test`).
Лид разложил гочу в проектный адаптер mewria («восстанавливать cp / touch, финальные гейты
после `--no-incremental`»), но рецепт, который её порождает, — в агенте плагина.

**Проблема.** `agents/coder.md:83-84`: «copy the file next to itself (`cp {file} {file}.orig`),
mutate, run the test, then `mv {file}.orig {file}`». Копия получает mtime момента копирования
(до мутации), `mv` возвращает файл с этим старым mtime — он старше выходов сборки мутанта.
Сборка, решающая по времени изменения (MSBuild и другие инкрементальные сборки по mtime),
считает выходы свежими и оставляет мутированную сборку: следующие гейты шага и следующие
пробы идут против мутанта — ложный зелёный или ложный красный без видимой причины.
Сборки по хэшу содержимого (turbo, tsc с `--incremental`) не страдают — поэтому в TS-прогонах
это не всплывало.

**Предложение.** `agents/coder.md` (и рецепт пробы у tester'а, когда появится): восстанавливать
`cp {file}.orig {file}` и затем удалять копию (или `mv` + `touch {file}`), чтобы mtime был
новее выходов; после серии проб — финальные гейты шага без инкрементального кэша, если адаптер
lang называет такой режим (у C# — `--no-incremental`). Адаптер lang получает строку «как
собрать без инкрементального кэша». Проектная строка mewria тогда снимается.

**Критерии приёмки.** Рецепт coder'а меняет mtime при восстановлении; порт lang знает
«полная пересборка»; проверка на C#-проекте: мутация, восстановление, сборка — мутант не выживает
в бинарнике.
