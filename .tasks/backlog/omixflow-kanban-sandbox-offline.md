**Контекст.** MEW-1, Start: `board.py checkout MEW-1 --to .tasks/MEW-1` из песочницы Bash
упал: «нет связи с origin: доска не обновлена (git@github.com: Permission denied
(publickey))». В песочнице недоступен ssh-агент (`SSH_AUTH_SOCK` в `~/.ssh/agent/…`); вне
песочницы `ssh -T git@github.com` и `git fetch` проходят. Одна попытка вне песочницы тоже
упала той же ошибкой, следующая прошла. Дальше оркестратор запускал все команды доски
и `state.py finish` вне песочницы (16 вызовов) и записал это в проектный адаптер mewria
(раздел «Песочница», правка без коммита).

**Проблема.**
1. При `tracker.push: true` каждая команда доски ходит в сеть, а песочница Claude Code
   ssh не пропускает. Адаптер `kanban` об этом молчит: сессия узнаёт на первом же `checkout`.
2. `checkout` без связи падает (`board.py`, `checkout()`: `refresh()` под блокировкой
   бросает ошибку), хотя чтение по адаптеру идёт из локальной доски, а раздел «Свежесть»
   велит без связи предупредить и работать с локальной копией. Восстановить рабочую копию
   офлайн нельзя.
3. Публикация из `state.py finish` в песочнице молча превращается в предупреждение
   на каждой фазе — карточка отстаёт, пока кто-то не запустит команду вне песочницы.

**Предложение.**
1. `adapters/tracker/kanban.md`, раздел «Песочница»: команды доски при `tracker.push: true`
   (записи, `checkout`, `pull`, публикация через `state.py`) запускаются вне песочницы
   Bash; без этого доска работает только локально. Проектные адаптеры строку не повторяют.
2. `checkout` при сбое `fetch` предупреждает и восстанавливает из локальной доски (как
   `pull` в «Свежести»); записи по-прежнему падают, неопубликованных записей нет.
3. `state.py`: предупреждение о несостоявшейся публикации называет причину (нет связи)
   и подсказку «запустить вне песочницы».

**Критерии приёмки.** Тест `checkout` без remote-связи → код 0 с предупреждением, копия из
локальной доски; раздел адаптера; mewria снимает свою строку «Песочница».
