**Контекст.** Гоча G-39 сессии MEW-2: «idle_notification continuation-агента приходит
раньше обработки уже лежащего в очереди дополнения — оркестратор дважды отправил дубль
(О1 архитектору, #3 coder'у)».

**Проблема.** По транскрипту сообщение агенту, который ещё работает, доходит до него только
после конца хода:
- architect: дополнение по О1 отправлено в 17:05:50, отчёт по пакету #1–#8 без О1 — 17:06:03,
  уведомление о простое — 17:06:13, повтор оркестратора «Apply О1=b now» — 17:06:23; агент
  ответил на дополнение в 17:07:36 и на повтор — «уже внесено» в 17:08:06;
- coder: дополнение по #3 — 19:01:06, отчёт без #3 — 19:02:20, повтор «Apply #3 now» —
  19:02:34; дополнение агент получил в 19:02:29, после отчёта, повтор — «already applied».
Оркестратор принял отчёт без дополнения за потерю сообщения. Цена — лишний ход агента
с полным контекстом (у coder'а 707k) и путаница в журнале.

**Решение (0.5.1).** `runtime.md`, «Отчёт агента»: одно задание за раз. Новое задание или
дополнение живому агенту уходит после его отчёта на текущее; решение, пришедшее раньше,
ждёт. Если сообщение уже ушло, отчёт без него — не потеря: ответ придёт следующим ходом,
повторять нельзя.

**Критерии приёмки.** Правило в одном месте, скилы implement и review на него не
противоречат.
