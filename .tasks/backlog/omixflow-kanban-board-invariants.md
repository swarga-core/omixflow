**Контекст.** Ревью ветки kanban перед шагом 10 плана; на `main` после выпуска 0.4.0 все
пункты на месте. Пути — `adapters/tracker/kanban/board.py` на `1de619a`.

**Проблемы.**

1. **`checkout --force` не восстанавливает копию, а дописывает.** `checkout()` (`:572-588`)
   пишет только файлы карточки, лишние файлы рабочей копии остаются. В
   `tests/test_board.py`, `test_checkout_protects_a_different_working_copy`, после
   `--force` неопубликованный `spec.md` остаётся в рабочей копии и уйдёт в карточку следующим
   `publish`, хотя разработчик выбрал «восстановить из карточки».
2. **`set` обходит инварианты `move`.** `move` разрешает резолюцию только при переезде
   в `done` (`:482-483`) и сбрасывает её в остальных колонках (`:488`); `set_fields()`
   (`:506-522`) пишет `resolution=canceled` в любой колонке, и `board.md` показывает
   «✗ canceled» у карточки в `backlog`. `set {эпик} parent={тот же эпик}` проходит:
   `check_parent()` (`:453-455`) проверяет только `kind: epic`.
3. **`set title=` не трогает `task.md`.** Заголовок `# {ID}: {название}` карточки остаётся
   старым, а `get`, `ref` и `board.md` берут новое название из `state.yaml`. После Start
   `task.md` принадлежит рабочей копии сессии, и публикация вернёт старый заголовок.
   Папка карточки сохраняет старый slug (косметика: путь разрешается по id).
4. **Формальные поля карточки в трёх местах.** `BOARD_OWNED` (`board.py:80`) и `CARD_FIELDS`
   (`scripts/state.py:78`) — один и тот же список, равенство линт не проверяет; `FORMAL`
   (`board.py:76`) не используется и отличается от обоих (есть `updated`, нет `imported`).
   Канон списка — `protocol/artifacts.md`, «Хранение в задаче трекера».
5. **git 2.31+.** `Board.__init__` вызывает `git rev-parse --path-format=absolute`
   (`:150`), флаг появился в git 2.31; `doctor` проверяет только наличие `git`.

**Предложение.**
1. `checkout --force` после записи удаляет файлы рабочей копии, которых нет в карточке
   (кроме игнорируемого адаптером, если такое появится); тест на исчезновение лишнего файла.
2. `resolution` убрать из `SETTABLE` (резолюция только через `move`) или разрешить только
   в `done`; `check_parent` отклоняет `parent == cid`.
3. `set title=` в `backlog` переписывает первую строку `task.md`, если она в форме
   `# {ID}: …`; после Start — ошибка с подсказкой править заголовок в рабочей копии.
4. Один список `CARD_FIELDS` в `omixflow_lib`, им пользуются `board.py` и `state.py`;
   `FORMAL` удалить; линт сверяет список с перечнем в `artifacts.md`.
5. Абсолютный путь вычислять в Python (`(root / out).resolve()`) без флага, либо `doctor`
   проверяет версию git при трекере kanban.

**Критерии приёмки.** Тесты на каждый пункт 1–3; один список формальных полей; доска
работает на git ниже 2.31 или `doctor` сообщает о версии.
