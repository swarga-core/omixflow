# Словарь OMIXFlow

Единственный источник терминов. Скилы, агенты, адаптеры и конфиг используют слова
отсюда и не вводят синонимов. В прозе допустим русский термин, в идентификаторах,
флагах, именах файлов и колонках таблиц используется английский.

## Процесс

| Термин | EN | Значение |
|---|---|---|
| пайплайн | pipeline | последовательность фаз, через которую проходит задача |
| фаза | phase | единица пайплайна в глобальном порядке: Refine, Start, Research, Spec, Plan, Implement, Review, Finalize; набор фаз задачи задаёт профиль |
| профиль | profile | именованное подмножество фаз со свойствами (`mutates`, `part_isolation`, `part_integration`, `finalize_artifact`, `triage`, `part_runner`); канон в `profiles.md`, нет профиля = `full` |
| блокирующий вопрос | blocking question | вопрос researcher'а, меняющий направление или объём части либо задачи; researcher ждёт ответа (`STATUS: blocked`) |
| отложенный вопрос | deferred question | вопрос, влияющий на будущее решение; пишется в Design Questions без ответа |
| передача | handoff | секция `## Handoff` research.md части для зависимых частей: факты, решения, затронутые файлы, открытые вопросы |
| `STATUS: blocked` | researcher blocked | отчёт researcher'а: агент жив и ждёт ответа на блокирующий вопрос; не путать со статусом части `blocked` |
| шаг | step | элемент plan.md; один шаг = один атомарный коммит с тест-чекпоинтом |
| тир | tier | размер задачи S, M или L; меняет состав исполнителей и число вызовов, но не инварианты |
| оркестратор | orchestrator | основная сессия Claude Code, исполняющая скил; координирует агентов, общается с разработчиком, сама код не пишет |
| агент | agent | субагент с ролью: researcher, architect, coder, tester, reviewer, web-fetcher |
| гейт | gate | именованная команда проверки из порта lang с критерием чтения результата: typecheck, test, lint, build, e2e |
| finding | finding | замечание reviewer'а с severity и category; контракт в review-cycle.md |
| эскалация | escalation | передача решения на уровень выше: от оркестратора разработчику после исчерпания лимита или при critical, от лида разработчику по политике (`E-{n}`) |
| точка решения | decision point | место скила пайплайна, где нужен ответ разработчика; идентификатор и режим в `dialog.md` |
| маршрут вопроса | question route | кому задаётся вопрос в точке решения; по умолчанию разработчик в этой сессии, с лидом по политике |
| лид | lead | сессия, координирующая сессии задач разработчика: принимает их вопросы в точках решения, решает или передаёт разработчику, ведёт журнал; `lead.md` |
| сессия задачи | task session | оркестратор задачи или части, запущенный с лидом; имя сессии равно id задачи, у части `{id}-{part}` |
| политика лида | lead policy | режим маршрута по точке решения: `developer`, `lead`, `lead-notify`, `precedent`, `direct`; `lead.policy` конфига |
| ветка лида | lead branch | `lead/{имя}` в worktree лида, в который лид не входит; журнал и настройки лида |
| интеграционная ветка | integration branch | база сессий задач под лидом и цель интеграции: ветка мультизадачи или назначенная линия; лид её в своём worktree не держит |
| приёмка мержа | merge acceptance | мерж лидом ветки сданной задачи в интеграционную ветку: план, санкция `A-{n}`, мерж без коммита, гейты на слитом дереве, коммит, `advisory` сессиям; `lead.md` |
| гоча | gotcha | особенность, найденная по ходу задачи: дефект плагина, особенность проекта или личное наблюдение; раскладывается на Finalize (`phases.md`); у сессии под лидом её раскладывает лид |
| сводный блок | lead board | управляемый блок `omixflow:lead` в описании родительской задачи: задачи под лидом, фазы, приёмки; строится из журнала |
| вето | veto | отмена разработчиком решения лида; цена отката по классу 1–3 (`lead.py veto-cost`), затем директива сессии; `lead.md` |
| санкция | approval | согласие разработчика на собственное действие лида, `A-{n}` в журнале |
| журнал лида | lead journal | решения `D-{n}`, эскалации `E-{n}`, прецеденты, обязательства и реестр сессий; каталог `_lead` каталога артефактов на ветке лида |
| прецедент | precedent | решение разработчика или поднятое им правило, которое лид применяет к равнозначному вопросу другой задачи; в режиме `precedent` только такое основание даёт лиду право решить |
| continuation | continuation | принцип «один спавн агента с именем, дальше SendMessage»: контекст агента живёт всю задачу |

## Задача

| Термин | EN | Значение |
|---|---|---|
| задача | task | единица работы с идентификатором, выданным адаптером трекера |
| id | id | идентификатор задачи в формате адаптера: `AL-822` у YouTrack, kebab-slug у local и none |
| постановка | statement | описание задачи, уточнённое в Refine |
| артефакты | artifacts | файлы задачи в `.tasks/{id}/`: task.md, state.yaml, log.md, research.md, spec.md, plan.md |
| состояние | state | машинно-читаемое положение задачи в пайплайне: `state.yaml` |
| журнал | log | человеко-читаемая история задачи: `log.md` |
| ветка задачи | task branch | `task/{id}` по умолчанию; шаблон в конфиге |
| базовая ветка | base branch | ветка, от которой ответвляется задача и куда она вливается; разрешается портом workspace |

## Мультизадача

| Термин | EN | Значение |
|---|---|---|
| доска | board | хранилище задач адаптера `kanban`: ветка `board`, открытая worktree в `.tasks/board/`; колонки-папки и вид доски `board.md` |
| карточка | card | задача на доске: папка `{колонка}/{ID}-{slug}/` с `task.md`, `state.yaml`, артефактами и `comments.md` |
| колонка | column | папка доски, она же статус задачи: `backlog`, `working`, `review`, `done` |
| рабочая копия | working copy | каталог артефактов задачи в дереве сессии при хранении артефактов в задаче трекера; временная, публикуется в задачу |
| эпик | epic | родительская задача трекера с дочерними задачами (поле `parent` у дочерних); не мультизадача: части мультизадачи живут внутри одной задачи |
| мультизадача | multitask | задача, части которой выполняются как самостоятельные задачи, каждая с пайплайном профиля мультизадачи и своими артефактами; в трекере это обычная задача с управляемым блоком `omixflow:multitask` |
| часть | part | единица мультизадачи; имеет slug, постановку, зависимости, владельца, статус, ветку |
| карта зависимостей | dependency map | явно объявленные зависимости частей друг от друга; ациклический граф, обязателен для старта |
| волна | wave | множество частей, готовых к выполнению одновременно: уровень топологической сортировки карты |
| владелец | owner | исполнитель, взявший часть в работу; логин из адаптера трекера |
| борд | board | таблица частей со статусами внутри управляемого блока в описании задачи |
| ветка мультизадачи | multitask branch | `task/{id}`; интеграционная ветка, куда вливаются части |
| ветка части | part branch | `task/{id}-{part}`; ответвляется от ветки мультизадачи; только при `part_isolation: worktree` |
| способ сдачи | delivery | как одиночная задача уходит в базу на Finalize: PR, интеграция в базу или сдача лиду; `workspace.delivery` |
| интеграция части | part integration | по профилю: squash или merge части в ветку мультизадачи (`integrate`) либо коммит каталога части по пути (`commit`) |
| статус части `blocked` | part blocked | часть остановлена с причиной в трекере; не путать с `STATUS: blocked` researcher'а |
| планировщик | scheduler | режим `research {id} --parts`: в одной сессии ведёт части профиля с `part_runner: scheduler` по готовности и репозиториям |
| синтез | synthesis | сводный `.tasks/{id}/research.md` мультизадачи по отчётам частей |
| репозиторий workspace | workspace repo | чужой репозиторий из `workspace.repos`, который немутирующие фазы читают |
| снимок | snapshot | `repos: {name: {ref, sha}}` в состоянии мультизадачи: sha чужих репозиториев на старте |
| research-worktree | research-worktree | worktree чужого репозитория на sha снимка, `.claude/worktrees/research-{id}` в нём; только для чтения |

## Расширение

| Термин | EN | Значение |
|---|---|---|
| порт | port | контракт ядра к внешнему миру: tracker, forge, lang, workspace; описан в `adapters/{port}/PORT.md` |
| адаптер | adapter | реализация порта: файл `adapters/{port}/{name}.md` с фронтматтером и правилами |
| возможность | capability | именованная операция порта; адаптер объявляет, какие реализует |
| расширение | extension | проектный адаптер с `extends`, добавляющий правила к базовому |
| замена | replacement | проектный адаптер без `extends`, полностью подменяющий базовый |
| конфиг проекта | project config | `.claude/omixflow/flow.yaml`; только значения |

## Запрещённые термины

| Не использовать | Почему | Использовать |
|---|---|---|
| подзадача, subtask | у мультизадачи части живут внутри одной задачи; у эпика это дочерние задачи | часть, part; дочерняя задача |
| этап, stage | двусмысленно: фаза пайплайна или часть мультизадачи | фаза либо часть |
| итерация (для частей) | занято доработкой задачи после возврата | часть |
| omix-workflow.md | старый конфиг предыдущего поколения | flow.yaml и protocol/ |
| Task tool | старое имя инструмента | Agent tool |

## Адресация

- Задача: `{id}` в формате адаптера трекера.
- Часть: `{id}/{part}` в тексте и командах; во флагах `--part {part}`.
- Ветка части: `task/{id}-{part}`. Слэш невозможен: git не позволяет одновременно
  существовать ссылкам `task/AL-9` и `task/AL-9/x`.
- Артефакты части: `.tasks/{id}/{part}/`.
- Агент задачи: `{role}-{id}`; агент части: `{role}-{id}-{part}`.
- Агент синтеза мультизадачи: `researcher-{id}`.
