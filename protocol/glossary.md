# Словарь OMIXFlow

Единственный источник терминов. Скилы, агенты, адаптеры и конфиг используют слова
отсюда и не вводят синонимов. В прозе допустим русский термин, в идентификаторах,
флагах, именах файлов и колонках таблиц используется английский.

## Процесс

| Термин | EN | Значение |
|---|---|---|
| пайплайн | pipeline | последовательность фаз, через которую проходит задача |
| фаза | phase | один из восьми этапов пайплайна: Refine, Start, Research, Spec, Plan, Implement, Review, Finalize |
| шаг | step | элемент plan.md; один шаг = один атомарный коммит с тест-чекпоинтом |
| тир | tier | размер задачи S, M или L; меняет состав исполнителей и число вызовов, но не инварианты |
| оркестратор | orchestrator | основная сессия Claude Code, исполняющая скил; координирует агентов, общается с разработчиком, сама код не пишет |
| агент | agent | субагент с ролью: researcher, architect, coder, tester, reviewer, web-fetcher |
| гейт | gate | именованная команда проверки из порта lang с критерием чтения результата: typecheck, test, lint, build, e2e |
| finding | finding | замечание reviewer'а с severity и category; контракт в review-cycle.md |
| эскалация | escalation | передача решения разработчику после исчерпания лимита или при critical |
| continuation | continuation | принцип «один спавн агента с именем, дальше SendMessage»: контекст агента живёт всю задачу |

## Задача

| Термин | EN | Значение |
|---|---|---|
| задача | task | единица работы с идентификатором, выданным адаптером трекера |
| id | id | идентификатор задачи в формате адаптера: `AL-822` у YouTrack, kebab-slug у local и none |
| постановка | statement | описание задачи, уточнённое в Refine |
| артефакты | artifacts | файлы задачи в `.tasks/{id}/`: task.md, state.yaml, log.md, research.md, spec.md, plan.md |
| состояние | state | машинно-читаемое положение задачи в пайплайне: `state.yaml` |
| журнал | log | человеко-читаемая история задачи: `log.md` |
| ветка задачи | task branch | `task/{id}` по умолчанию; шаблон в конфиге |
| базовая ветка | base branch | ветка, от которой ответвляется задача и куда она вливается; разрешается портом workspace |

## Мультизадача

| Термин | EN | Значение |
|---|---|---|
| мультизадача | multitask | задача, части которой выполняются как самостоятельные задачи, каждая со своим полным пайплайном, веткой и артефактами; в трекере это обычная задача с управляемым блоком `omixflow:multitask` |
| часть | part | единица мультизадачи; имеет slug, постановку, зависимости, владельца, статус, ветку |
| карта зависимостей | dependency map | явно объявленные зависимости частей друг от друга; ациклический граф, обязателен для старта |
| волна | wave | множество частей, готовых к выполнению одновременно: уровень топологической сортировки карты |
| владелец | owner | исполнитель, взявший часть в работу; логин из адаптера трекера |
| борд | board | таблица частей со статусами внутри управляемого блока в описании задачи |
| ветка мультизадачи | multitask branch | `task/{id}`; интеграционная ветка, куда вливаются части |
| ветка части | part branch | `task/{id}-{part}`; ответвляется от ветки мультизадачи |
| интеграция части | part integration | squash части в ветку мультизадачи одним коммитом |

## Расширение

| Термин | EN | Значение |
|---|---|---|
| порт | port | контракт ядра к внешнему миру: tracker, forge, lang, workspace; описан в `adapters/{port}/PORT.md` |
| адаптер | adapter | реализация порта: файл `adapters/{port}/{name}.md` с фронтматтером и правилами |
| возможность | capability | именованная операция порта; адаптер объявляет, какие реализует |
| расширение | extension | проектный адаптер с `extends`, добавляющий правила к базовому |
| замена | replacement | проектный адаптер без `extends`, полностью подменяющий базовый |
| конфиг проекта | project config | `.claude/omixflow/flow.yaml`; только значения |

## Запрещённые термины

| Не использовать | Почему | Использовать |
|---|---|---|
| эпик, epic | в трекерах это задача с реальными дочерними задачами; наш механизм другой | мультизадача, multitask |
| подзадача, subtask | в трекерах это дочерняя задача; у нас части живут внутри одной задачи | часть, part |
| этап, stage | двусмысленно: фаза пайплайна или часть мультизадачи | фаза либо часть |
| итерация (для частей) | занято доработкой задачи после возврата | часть |
| omix-workflow.md | старый конфиг предыдущего поколения | flow.yaml и protocol/ |
| Task tool | старое имя инструмента | Agent tool |

## Адресация

- Задача: `{id}` в формате адаптера трекера.
- Часть: `{id}/{part}` в тексте и командах; во флагах `--part {part}`.
- Ветка части: `task/{id}-{part}`. Слэш невозможен: git не позволяет одновременно
  существовать ссылкам `task/AL-9` и `task/AL-9/x`.
- Артефакты части: `.tasks/{id}/{part}/`.
- Агент задачи: `{role}-{id}`; агент части: `{role}-{id}-{part}`.
