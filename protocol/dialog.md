# Диалог с разработчиком

Три режима. Критерий выбора: **ответ выбирает маршрут или меняет содержание?**

1. **AskUserQuestion (AUQ)**: ответ выбирает маршрут из конечного набора. От двух до
   четырёх вариантов, рекомендуемый первым с пометкой «(Recommended)», контекст
   в description вариантов, до четырёх вопросов за вызов.
2. **Свободный текст**: ответ может изменить содержание (постановку, архитектуру,
   формулировки) или ситуацию нельзя перечислить заранее.
3. **Гибрид**: длинный контекст (превью, сводка, разбор проблемы) текстом, затем
   компактный AUQ только для решения. Правило выхода: выбор «Other», «Поправить»,
   «Альтернатива» или несогласие переводит в текстовый диалог, а не в повторный AUQ.

## Точки решения

Точка решения это место скила пайплайна, где нужен ответ разработчика. Скил называет
точку по идентификатору («спросить в точке `finding`») и не выбирает режим сам: режим
задаёт таблица, маршрут задаёт раздел «Маршрут вопроса». Вид точки: `содержание`
(ответ меняет постановку, решения или объём задачи), `маршрут` (развилка пайплайна),
`внешнее` (подтверждение внешнего действия). Идентификаторы содержательных точек
и развилок маршрута пишутся в kebab-case, внешних действий как `{порт}.{действие}`.

| id | Вид | Точка | Режим |
|---|---|---|---|
| `statement` | содержание | уточнение постановки на Refine | текст; перечислимые поля AUQ |
| `decomposition` | содержание | декомпозиция мультизадачи: профиль, состав частей, репозитории частей, карта зависимостей | текст; перечислимое AUQ |
| `design-question` | содержание | design questions после Research; отложенные вопросы синтеза | по разделу «Design questions» |
| `research-blocking` | содержание | блокирующий вопрос researcher'а | гибрид: контекст текстом, варианты AUQ, «Other» → текст |
| `handoff` | содержание | открытые вопросы Handoff при завершении части немутирующего профиля | как `design-question` |
| `finding` | содержание | эскалация findings: `warning [architecture]`, `critical`, low-confidence, нерешённые после лимита проходов | гибрид: Принять (Recommended) / Отклонить / Альтернатива |
| `scope-change` | содержание | масштаб вырос: тир, изменения в нескольких репозиториях, пересечение с частями в работе, конфликт spec и plan | текст |
| `deadlock` | содержание | тупики: лимит попыток coder или tester, конфликт слияния, остановка без очевидных вариантов | гибрид: вручную / пропустить / остановить, нестандартное текстом |
| `reconcile` | содержание | рассинхрон git, трекера и блока мультизадачи | гибрид: дельта текстом, затем решение |
| `gotchas` | содержание | маршрутизация гочей на Finalize | гибрид: превью, затем Добавить (Recommended) / Поправить / Пропустить |
| `resume` | маршрут | продолжить с фазы, перезапустить или начать заново; артефакт существует, пересоздать ли; сначала Refine или исходная формулировка | AUQ |
| `part-take` | маршрут | взять часть мультизадачи | AUQ |
| `part-blocked` | маршрут | заблокированная часть; зависимость от пропущенной части | гибрид |
| `part-integrate` | маршрут | интеграция части | гибрид |
| `delivery` | маршрут | способ сдачи задачи на Finalize: PR, интеграция в базу или сдача лиду | AUQ |
| `tracker.describe` | внешнее | запись описания задачи в трекер: уточнённая формулировка, блок мультизадачи | гибрид: превью, затем Записать (Recommended) / Поправить / Пропустить |
| `tracker.comment` | внешнее | комментарий в трекер | гибрид: превью, затем Добавить (Recommended) / Поправить / Пропустить |
| `tracker.status` | внешнее | смена статуса в трекере | AUQ |
| `forge.pr` | внешнее | создание PR | гибрид: превью, затем Создать (Recommended) / Поправить / Пропустить |
| `workspace.branch` | внешнее | ветка или worktree задачи, ветка мультизадачи, research-worktree | AUQ |
| `workspace.exit` | внешнее | выход из worktree, снос worktree и веток | AUQ |
| `workspace.integrate` | внешнее | влить ветку задачи в базу без PR (`workspace.integration`) | гибрид: превью (ветка, база, файлы, сообщение коммита), затем Влить (Recommended) / Поправить / Пропустить |

Итоги фаз и информирование («задача вернулась на доработку», «мультизадача не
декомпозирована», сводка планировщика в конце прогона) точками решения не являются:
текст, ответа не ждать.

Скилы вне пайплайна задачи (`create`, `doctor`, `pr-review`) идентификаторов точек
не используют и выбирают режим по критерию выше; метаданные задачи из enum-полей
трекера идут через AUQ.

## Маршрут вопроса

Вопрос в точке решения задаётся по маршруту. Без лида маршрут один: разработчик в этой
сессии, в режиме точки из таблицы. Сессия, запущенная с лидом (поле `lead` состояния
задачи), выбирает маршрут по политике `lead.policy` конфига: `lead.md`, раздел
«Маршрут вопроса». Решение записывается в log.md задачи с идентификатором точки
и основанием (`artifacts.md`, раздел «log.md»).

## Design questions

Весь список одним сообщением: для каждого вопроса `Q{n}`, суть, короткий контекст
(`path:line`, факты), варианты буквами с ценой каждого, рекомендация; связи между
вопросами названы явно. Ответ ждать свободным текстом: разработчик отвечает одним
сообщением и может дописать к варианту условия. Ответ записывается в артефакт дословно
как `A{n}`, вместе с условиями. Через AUQ задаётся только одиночный вопрос с двумя-четырьмя
вариантами, не связанный с другими.

## Дополнительно

- Содержательные вопросы и подтверждения внешних действий не смешиваются в одном
  AUQ-вызове.
- Findings эскалируются пакетами не больше четырёх; каждый пункт решается отдельно,
  один вопрос никогда не покрывает несколько пунктов.
- Finding, требующий обсуждения по существу, идёт сразу текстом, минуя AUQ.
- Текстовый override всегда допустим: «включаем всё», «всю группу» и подобное
  трактуются буквально.
- Язык общения с разработчиком задаёт его пользовательский CLAUDE.md; внутренний
  протокол агентов на английском.
