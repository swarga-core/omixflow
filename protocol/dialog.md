# Диалог с разработчиком

Три режима. Критерий выбора: **ответ выбирает маршрут или меняет содержание?**

1. **AskUserQuestion (AUQ)**: ответ выбирает маршрут из конечного набора. От двух до
   четырёх вариантов, рекомендуемый первым с пометкой «(Recommended)», контекст
   в description вариантов, до четырёх вопросов за вызов.
2. **Свободный текст**: ответ может изменить содержание (постановку, архитектуру,
   формулировки) или ситуацию нельзя перечислить заранее.
3. **Гибрид**: длинный контекст (превью, сводка, разбор проблемы) текстом, затем
   компактный AUQ только для решения. Правило выхода: выбор «Other», «Поправить»,
   «Альтернатива» или несогласие переводит в текстовый диалог, а не в повторный AUQ.

## Канон по точкам

| Точка взаимодействия | Режим |
|---|---|
| Уточнение постановки; открытые design questions; нестандартные остановки: конфликт слияния, рассинхрон git и трекера, тупики без очевидных вариантов | текст |
| Design questions с перечислимыми вариантами; метаданные задачи из enum-полей трекера | AUQ |
| Ветвление; «продолжить с исходной формулировкой?»; резюм «продолжить с {фазы}?»; «артефакт существует, пересоздать?»; смена статуса в трекере; выход из worktree; взять часть мультизадачи | AUQ |
| Эскалация findings (Принять (Recommended) / Отклонить / Альтернатива); тупики coder и review (вручную / пропустить / остановить); запись в трекер и создание PR (превью, затем Записать (Recommended) / Поправить / Пропустить); интеграция части; заблокированная часть; реконсиляция борда | гибрид |
| Блокирующий вопрос researcher'а | гибрид: контекст текстом, варианты AUQ, «Other» → текст |
| Завершение части немутирующего профиля: открытые вопросы Handoff для зависимых | текст или AUQ по характеру вопроса |
| Отложенные вопросы при синтезе | как design questions |
| Создание research-worktree | AUQ |
| Итоги фаз, информирование («задача вернулась на доработку», «мультизадача не декомпозирована»), сводка планировщика в конце прогона | текст, ответа не ждать |

## Дополнительно

- Содержательные вопросы и подтверждения внешних действий не смешиваются в одном
  AUQ-вызове.
- Findings эскалируются пакетами не больше четырёх; каждый пункт решается отдельно,
  один вопрос никогда не покрывает несколько пунктов.
- Finding, требующий обсуждения по существу, идёт сразу текстом, минуя AUQ.
- Текстовый override всегда допустим: «включаем всё», «всю группу» и подобное
  трактуются буквально.
- Язык общения с разработчиком задаёт его пользовательский CLAUDE.md; внутренний
  протокол агентов на английском.
