# Порт forge

Хостинг кода: pull request'ы и ревью на них. `pr_create` нужен фазе Finalize;
остальные возможности нужны скилу ревью PR, без них он недоступен, а пайплайн
разработки работает.

## Возможности

| Возможность | Обязательна | Что делает | Кто использует |
|---|---|---|---|
| current_user | да | логин и отображаемое имя для подписи ревью и фильтра «мои ревью» | review |
| pr_create | да | создать PR из ветки задачи в base с заголовком и телом; вернуть URL | finalize |
| pr_get | нет | метаданные PR: номер, заголовок, head и base с SHA, автор, состояние, тело | review |
| pr_files | нет | список файлов с патчами для валидации строк inline-комментариев | review |
| pr_reviews | нет | опубликованные ревью с автором, состоянием, телом и SHA коммита | review |
| pr_threads | нет | треды inline-комментариев с флагами resolved и outdated и id комментариев | review |
| review_publish | нет | опубликовать ревью: тело, событие approve, comment или request_changes, inline-комментарии с привязкой к строкам конкретного SHA | review |
| reply | нет | ответить в существующий тред | review |
| permalink | нет | ссылка на файл и строку, привязанная к SHA, не к ветке | review |

## Правила ядра, которые адаптер обязан поддержать

- Inline-комментарий может быть привязан только к строке, входящей в diff hunk PR;
  адаптер отдаёт `pr_files` с патчами, ядро валидирует до публикации.
- Подсчёт раундов ревью ведётся по ревью с непустым телом от текущего пользователя;
  адаптер описывает, какие записи хостинг генерирует автоматически и как их
  отфильтровать.
- Ответы в тред публикуются последовательно, не параллельно, и отдельно от батча
  нового ревью.
- Подпись в теле ревью это имя из `current_user`; в ответах внутри тредов подписи нет.

## Конфиг

```yaml
forge:
  adapter: github
```

## Авторинг адаптера

Детерминированные процедуры (сборка payload ревью, валидация строк против патчей,
выборка тредов) реализуются скриптами адаптера и объявляются в `scripts`, а не
описываются как инструкции «напиши скрипт».
