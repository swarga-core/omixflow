# Порт lang

Всё, что зависит от языка и инструментария: как проверять, как называть тесты,
что считается подавлением ошибки, чем ходить по коду. Агенты ядра говорят
«прогони гейт typecheck», а не «запусти компилятор». Проект может перечислить
несколько языков (`lang: [ts, go]`); гейты тогда объединяются, конвенции применяются
по расширению файла.

## Возможности

| Возможность | Обязательна | Что даёт | Кто использует |
|---|---|---|---|
| verify | да | именованные гейты с командой, областью и критерием чтения результата | coder, tester, reviewer, doctor |
| test_conventions | да | шаблоны имён тестовых файлов, типы тестов, как запустить один файл или один тест | tester, coder |
| suppressions | да | список запрещённых способов заглушить ошибку | coder, tester, reviewer |
| navigation | да | инструменты навигации и рефакторинга, доступные для языка, с условиями применимости | researcher, architect, coder, reviewer |
| deps_setup | да | команда установки зависимостей | хук worktree, doctor |
| workspace_layout | нет | как найти пакеты монорепо и запустить гейт в одном пакете | researcher, coder |
| long_running | нет | какие гейты запускать отсоединённо через `scripts/gate.py` и ждать опросами (`protocol/runtime.md`, «Гейты»); проект добавляет свои через `background: true` в `verify.*` | coder, tester, reviewer |

## Гейты

Фиксированный словарь имён: `typecheck`, `test`, `lint`, `build`, `e2e`, `visual`
(визуальная регрессия в браузере, снимки). Проект задаёт команды в `verify.*`, адаптер
задаёт дефолты и критерии. Гейт `test` обязателен, остальные по наличию в проекте.
Критерии чтения результата:

| Критерий | Значение |
|---|---|
| exit-code | ноль это зелёный |
| zero-diagnostics | ноль диагностик в выводе, даже если код возврата ноль; учесть обрезку вывода линтера |
| no-new-diagnostics | число и состав диагностик не хуже baseline, замеренного на базовой ветке в начале задачи; для репозиториев с накопленным долгом линтера |
| rerun-compare-set | красный прогон повторяется без изменений; совпавший набор упавших имён это дефект, изменившийся или пустой это прогрев |

Форма записи гейта в конфиге: строка команды (критерий exit-code) или объект
`{cmd, criterion, scope, background, when}`. `when` перечисляет области изменений,
при которых гейт обязателен даже если по умолчанию он не в основном наборе.

Если сборка языка инкрементальна по времени изменения файлов, адаптер называет в разделе
`verify` способ полной пересборки (флаг или команду): после мутационных проб coder гоняет
гейты шага им, потому что инкрементальный кэш может держать мутанта.

## Подавления

Адаптер перечисляет конструкции, которые запрещено добавлять как «фикс»: директивы
игнорирования диагностик, приведения к произвольному типу, пропуск тестов. Coder и tester
их не пишут и перед отчётом проходят изменённые файлы этим списком (линтер ловит не все
конструкции); reviewer ищет их структурно во всём диффе ветки. Исключение допускается
только с комментарием-обоснованием и упоминанием в отчёте агента.

Запрет касается изменений, остающихся в дельте. Мутационная проба может временно
изменить и файл, который адаптер или проект запрещают править (список запрещённых
символов, общий конфиг), если откатывает его в той же пробе и дифф файла после неё пуст.

## Навигация

Базовый набор для всех языков это LSP-навигация (serena): обзор символов файла,
чтение символа, поиск ссылок, переименование. Адаптер добавляет языковые бустеры
с условием применимости (например, инструмент рефакторинга, требующий конфиг
компилятора в корне пакета).

Инструменты навигации активируются на абсолютном `PROJECT_ROOT` из промпта спавна,
а не на cwd: сессия может находиться в другом репозитории.

## Конфиг

```yaml
lang: [ts]
verify:
  typecheck: pnpm check-types
  test: pnpm test
  lint: { cmd: pnpm lint, criterion: zero-diagnostics }
  e2e: { cmd: pnpm e2e, criterion: rerun-compare-set, background: true, when: [i18n, styles, mocks] }
```

## Авторинг адаптера

- Не переписывать принципы агентов: SDD, мутационная проверка тестов, честная
  эскалация живут в ядре.
- Идиомы запуска, которые тихо делают не то (фильтр тестов, прогоняющий всё;
  линтер, печатающий help с нулевым кодом), документируются здесь как правила
  с точной формой команды.
