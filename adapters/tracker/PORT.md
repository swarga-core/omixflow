# Порт tracker

Источник задач: откуда пайплайн берёт постановку, куда пишет уточнения, статусы,
комментарии и блок мультизадачи. Ядро оперирует абстрактными статусами
и абстрактными операциями; адаптер отображает их на конкретный трекер.

## Возможности

| Возможность | Обязательна | Что делает | Кто использует |
|---|---|---|---|
| identify | да | по строке аргумента определить, это id задачи этого адаптера или свободная формулировка; вернуть нормализованный id | все скилы на входе |
| get | да | вернуть задачу: id, summary, description, type, priority, произвольные поля, ссылки | refine, start, develop |
| update_description | да | заменить описание целиком; ядро использует это для управляемых блоков и уточнённой формулировки | refine, multitask |
| comment | да | добавить комментарий | start, finalize, multitask |
| set_status | да | перевести задачу в абстрактный статус: `in_work`, `in_review`, `done`; отображение в `tracker.status_map` | start, finalize |
| current_user | да | логин текущего пользователя для `owner` и подписи | multitask, review |
| comments | нет | прочитать комментарии, с пагинацией если нужно | refine, develop при возврате на доработку |
| create | нет | создать задачу из постановки с дефолтами `tracker.create_defaults` | create |
| link | нет | связать задачи | create, парные задачи |
| search | нет | найти задачи по запросу адаптера | refine, yt-commit-подобные сценарии |
| tag | нет | добавить или снять тег | multitask (`multitask`) |
| parts_as_issues | нет | материализовать части мультизадачи дочерними задачами; зарезервировано | multitask, будущее |

## Управляемые блоки

Ядро хранит в описании задачи блоки между маркерами
`<!-- omixflow:{kind}:start -->` и `<!-- omixflow:{kind}:end -->`. Адаптер обязан
уметь: найти блок, заменить содержимое только между маркерами, дописать блок в хвост,
если его нет. Правило «прочитать перед записью, перечитать после» описано
в `protocol/multitask.md` и обязательно для любой реализации `update_description`.

## Уточнённая формулировка

Refine дописывает в описание секцию `## Уточнённая формулировка`, не удаляя исходный
текст. Start читает эту секцию, если она есть.

## Конфиг

```yaml
tracker:
  adapter: youtrack           # имя адаптера
  project: AL                 # ключ проекта, если трекер требует
  id_pattern: "^[A-Z]+-\\d+$" # переопределение шаблона id адаптера
  status_map:                 # абстрактный статус → статус трекера
    in_work: In Work
    in_review: Waiting for review
    done: Finished
  create_defaults:            # поля при create
    Type: Task
  dir: .tasks/backlog         # для адаптера local: каталог задач
```

## Авторинг адаптера

- Каждая возможность описывается как инструкция: какой инструмент вызвать, с какими
  аргументами, что вернуть, какие ограничения инструмента учесть.
- Ограничения трекера (лимиты пагинации, отсутствие патча описания, права на теги)
  документируются в адаптере, а не в ядре.
- Адаптер `none` реализует `required` пустыми операциями и хранит статус только
  в `state.yaml`; он нужен, чтобы пайплайн работал без трекера.
