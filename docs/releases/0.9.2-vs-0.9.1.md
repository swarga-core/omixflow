# OMIXFlow: 0.9.1 против 0.9.2

Выпуск из одного пункта: модель сессии-оркестратора задачи задаётся явно и видна в журнале.
Пайплайн, фазы и правила протокола прежние. Набор omixflow-revision (G-66, G-70, порядок секций
журнала в `stats.py`, ADR в счёте `plan.py files`, модель researcher'а для M) идёт следующим номером.

## 1. В двух словах

| | 0.9.1 | 0.9.2 |
|---|---|---|
| Модель сессии задачи | не задаётся: `sessions.py launch` без `--model`, сессия на модели родителя или харнесса | `models.orchestrator` проекта (иначе `models.strong`), всегда передаётся `--model`; разработчик может назвать другую для задачи |
| Знает ли сессия модель запуска | нет | да: `{model}` в промпте → `develop --model` → `state.yaml` `model_requested` |
| Где видна модель | только в `cost.py session` | `state.yaml` (`model`, по транскрипту), строка «Стоимость» каждой фазы; «(запущена на …)», если идёт не на модели запуска |
| Fable в `cost.py` | `phase` — коэффициент 1 (как Opus); `session` — выведенный из `cost-state` с двойной часовой надбавкой (T-10: 2,045) | 1,8 по умолчанию; выведенный — с разбивкой кэша на 5-минутный и часовой (T-10: 1,856) |
| После `claude respawn` | не проверено | модель запуска сохраняется (2.1.302) |

## 2. Что было и что меняется

У разработчика в `~/.claude/settings.json` стоит `"model": "opus"`, а оркестраторы Swarga AI
Studio, запущенные без `--model`, шли на Fable. Запросы оркестратора по транскриптам
(на 2026-10-17, по requestId — та же единица, что печатает строка «Стоимость»):

| Сессия | Модели по времени |
|---|---|
| swais-lead | Fable 251 |
| T-10 | Fable 190, в том числе после `respawn` |
| T-11 | Opus 246 (лид запускал с Opus) |
| T-12 | Fable 164 |
| T-13 | Fable 37 → Opus 60 |
| T-14 | Fable 53 → Opus 52 |

Фоновая сессия берёт модель родителя или умолчание харнесса, а не настройки. Переход на Opus
в T-13 и T-14 — ручное переключение разработчиком через `/model`.

Fable по `cost-state` харнесса дороже Opus в 1,825 раза (медиана 16 сессий с обеими моделями,
разброс 1,48–2,33; в T-10 — 1,856). Единой цены нет: по прейскуранту Fable в 2,5 раза дороже на
input, output и записи кэша и в 1,25 раза на чтении кэша, так что коэффициент — среднее по
нагрузке. Прежний вывод из `cost-state` взвешивал все записи кэша как 5-минутные, а Fable пишет
часовые; часовая надбавка входила в его коэффициент второй раз (2,045 в T-10). Оркестратор T-10
стоил $45,51 из $134,47 при 190 запросах; у семи задач базы на Opus (T-5…T-9, T-11, T-18) медиана
около $28, разброс $17–41 (разбор omixflow-revision и ревью выпуска). `cost.py phase`
коэффициенты из `cost-state` не выводит (запись появляется, только когда процесс выходит) и Fable
в таблице умолчаний не знал: журнал T-10 показал 33,3M cost_eq; `session` по той же сессии
теперь даёт 41,0M (с выведенным 1,856), с умолчанием 1,8 — 40,5M.

**Сравнения по долларам.** До 0.9.2 модель оркестратора не фиксировалась. Пары 0.9 против базы
и T-13/T-14 (Fable, затем Opus) по долларам и cost_eq сопоставимы только с поправкой на модель:
разбор пар берёт её по временным меткам транскрипта.

## 3. Цена и совместимость

- Новых фаз, проходов и агентов нет. Строка «Стоимость» длиннее на поле «оркестратор …»; `stats.py`
  читает только её начало (`- Стоимость: {N}M cost_eq`).
- Проект без `models.orchestrator` получает `models.strong` (по умолчанию `opus`): сессии лида
  пойдут на Opus, а не на модели лида. Проект, которому нужна другая модель, задаёт ключ. SwAIS
  и mewria ключа не задают — у них Opus.
- Идущие сессии (T-13, T-14) это не трогает: модель идущей сессии меняется только изнутри,
  `/model`.
- `cost.py session` по завершённой сессии выводит коэффициенты из её `cost-state`, теперь
  с разбивкой кэша; cost_eq ролей на Fable в старых сводках был завышен примерно на 10 % (доли
  сдвигаются меньше: оркестратор T-10 — 40 % вместо 42 %).

## 4. Что проверить на следующих прогонах

- `sessions.py launch` без `--model` в проекте SwAIS даёт `"model": "opus", "model_source":
  "config"`; строка `## Start ✅` новой задачи называет `claude-opus-…` без пометки
  «(запущена на …)», а `state.yaml` — `model_requested: opus`.
- Сумма строк «Стоимость» задачи сходится с `cost.py session` в пределах побочных запросов харнесса.
