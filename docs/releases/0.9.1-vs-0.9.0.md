# OMIXFlow: 0.9.0 против 0.9.1

Выпуск исправлений по первым прогонам на 0.9.0: Swarga AI Studio T-10 и T-12 под лидом swais-lead
и снятие правила R-1 после перехода SwAIS на 0.9.0. Форма пайплайна, фазы и правила протокола
те же. Что изменилось: как адресуются агенты, как снимается правило лида, где лежит копия
мутационной пробы, что значит `n/a` в BYTES CHECK и что считается в порог тира. Правила протокола
из тех же прогонов (G-66: текст механизма в Decisions против смены решения; G-70: непроверенный
факт из NOTES как основание решения лида) ждут следующего выпуска.

## 1. В двух словах

| | 0.9.0 | 0.9.1 |
|---|---|---|
| Адрес агента | `name` обязателен, SendMessage по имени; `agent_ctx.py {имя}` | имя роли — в `name`, когда харнесс его принимает, и в `description`; адрес — имя или `agentId` из результата спавна, он в `state.yaml`; `agent_ctx.py` по id и по имени, `--list` |
| Ротация без транскрипта | «объём из уведомления, если в нём есть usage» | то же, с названным полем: `subagent_tokens` — контекст на конец хода |
| Снятое правило лида | снять нельзя: `replace` только для решений, `list` и `precedents` отдают правило | `lead.py rule-retire R-n --decision D-m`; бриф и `precedents` берут только действующие |
| Копия мутационной пробы | `PATH.orig` рядом с файлом | `{git-dir}/omixflow-probes/{путь}.orig`; `restore` без `--file` — все оставшиеся |
| BYTES CHECK | строка на каждую не-ASCII строку или `n/a`; скрипт проверял только «не n/a» | строка на файл (кириллица, типографика; невидимых и escape нет) или строка на символ; скрипт сверяет, что назван каждый файл |
| Порог тира | тестовые файлы по `tests.files` (`*.test.*`) вне счёта | плюс тестовая поддержка `tests.support` (`test/`, `fixtures/`, `__mocks__/`, `test-utils/`) вне счёта |

## 2. Что было в прогонах и что меняется

### Агенты без имени (G-65)

С Claude Code 2.1.300 инструмент Agent не принимает `name`. В T-10 (2.1.300–2.1.301) ни в одном
из 8 `.meta.json` субагентов сессии имени нет; в T-8, T-9 и T-11 на 2.1.296 оно было. Оркестратор T-10
сам перешёл на agentId в `state.yaml`, а `agent_ctx.py`, который ищет по имени, на id отвечал
кодом 3 — «транскрипт агента не найден: …/subagents»; лид прочитал это как «каталога нет», хотя
все 8 транскриптов лежали на месте. Ротация coder'а прошла по `subagent_tokens` уведомления:
последнее перед третьим шагом — 348 997, после него — 497 532 (по транскрипту — 494 886).

0.9.1 описывает адрес агента одним правилом (`runtime.md`, «Спавн агентов»), скрипт находит
агента по id и печатает список субагентов сессии. Старые `state.yaml` с именами работают: имя
агента, заспавненного до обновления харнесса, в его `.meta.json` есть.

**Ожидаемый эффект.** Проверка перед заданием снова идёт скриптом по транскрипту, в том числе
у агентов без имени; уведомление остаётся запасным путём, и его поле теперь названо. Решения
ротации в T-10 это не меняет: перед третьим шагом было 349k при пороге 350k, перескок до 498k
за одно задание `tiers.md` допускает.

### Снятие правила лида (G-61)

Правило R-1 SwAIS («план превышает `m_max_files`, по остальным признакам M — тир остаётся M, лид
решает сам») с 0.9.0 противоречит протоколу: продолжение сверх порога — исключение разработчика.
Разработчик правило снял, лид заменил основание D-163 на D-238, но `replace R-1` отказал, а
`list --type rule` отдавал R-1 как действующее. Лид после перезапуска взял бы его в брифы.

### Копия пробы в каталоге миграций (G-69)

node-pg-migrate грузит любой файл каталога миграций, и копия `.orig` рядом с файлом становится
второй миграцией на время пробы. В T-12 из 65 проб 17 проб миграции coder сделал своим скриптом
(копия вне каталога, восстановление со сверкой байт): `probe.py` повторили руками. Теперь копия
лежит в git-каталоге дерева, как логи `gate.py`; тот же класс закрыт для любых каталогов с
автозагрузкой (плагины, `conf.d`, Unity `Assets/`).

### BYTES CHECK и кириллица (G-71)

В T-12 coder проверил дифф по байтам, невидимых символов и escape не нашёл и написал
`n/a: escapes нет; не-ASCII — только кириллица…`. Шаблон же понимает `n/a` как «дифф только из
ASCII». `report.py` вернул шаг без правок кода, а исправленный отчёт перечислил строки кириллицы
по диапазонам на файл. В русскоязычном проекте `n/a` почти не бывает: 0.9.1 даёт короткую форму
по файлу и сверяет покрытие.

### Тестовая поддержка в пороге (G-67)

Проза адаптера ts называла `test/`, `fixtures/`, `__mocks__/` и `test-utils/` тестовой поддержкой
(её правит tester), но `plan.py files` отличал тесты только по `*.test.*`. В T-10 план M насчитал
31–32 нетестовых файла при пороге 30, без хелперов — 29 (22 файла кода и документации и 7 записей
ADR), и вопрос ушёл разработчику как исключение (E-42 → D-254). С `tests.support` такой план
порог не превышает.

## 3. Цена и совместимость

- Никаких новых фаз, проходов или агентов. Изменения — в скриптах (`agent_ctx.py`, `lead.py`,
  `probe.py`, `report.py`, `plan.py`), формате двух секций отчёта и тексте адресации агентов.
- Возвраты отчёта вида T-12 (правка только BYTES CHECK) — минус круг coder'а и `report.py`
  на шаг с кириллицей в диффе; лишние эскалации порога вида T-10 — минус вопрос разработчику.
- SwAIS: правило R-1 снято до выпуска, в журнале его снятия нет — лиду один раз `lead.py
  rule-retire R-1 --decision D-238`; подсказка назовёт решения в точке `scope-change`, которые
  `precedents` ещё отдаёт (D-30, D-35, D-152, D-222 на копии журнала): те, что держат R-1, —
  `lead.py replace D-k --with D-238`.
- Обратная совместимость: `agent_ctx.py {имя}` работает как раньше; `probe.py restore --file`
  находит и копию старого формата (`restore` без `--file` — только копии в git-каталоге); JSON `plan.py files` получил поле `support`, остальные поля
  прежние. Проектный адаптер lang без `tests.support` считает как 0.9.0.

## 4. Что проверить на следующих прогонах

- Сессия на Claude Code 2.1.300+: `agent_ctx.py {agentId}` даёт `context` перед каждым заданием,
  адреса агентов — в `state.yaml`, в log.md — имена ролей; после `respawn` агенты продолжаются по id из
  `state.yaml`.
- Лид после перезапуска: в брифе нет снятых правил (`list --type rule --open`).
- Пробы миграций SwAIS идут через `probe.py batch`, без самодельных скриптов.
- Отчёты coder'а с кириллицей: BYTES CHECK в форме по файлу проходит `report.py check` с первого
  раза.
